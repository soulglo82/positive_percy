# Stage 1 · Parent-created reward image picker

> **Proposed library, not selected icons.** This is a broad **MIT-licensed Phosphor Duotone** browse set for parents creating their own rewards. It is safe to implement as a software asset library subject to the MIT notice; Streamline Plump Duo is deliberately **not inside this end-user picker** pending a specific redistribution/licensing decision. [Back to index](START_HERE.md).

## How the feature would work

A parent enters the reward title and points, chooses **an icon category**, searches by keyword or browses visual tiles, previews the choice at reward-card size and saves. The chosen semantic asset ID is stored with the reward. Existing emoji rewards continue working without destructive changes.

**No individual icon is chosen by this document.** Category membership and labels are design candidates that you can reorganise. **144 catalogue placements, 115 unique icons**, shown below from their actual official SVG files.

## Parent reward-picker interaction requirements

| Question | Proposal, subject to your approval |
|---|---|
| Who can choose? | Authenticated parent / shared carer only if authorised; no child login |
| Scope | Reward illustration/icon field; not a points-currency replacement |
| Icon grid | 3 columns on a narrow phone, 4–6 on wider layouts; icon rendered at 40–48px |
| Search | Match labels/keywords in metadata, not a third-party network search |
| Preview | 64px card with real icon, name and required points |
| Save | Stable `asset_id` (e.g. `phosphor:game-controller:duotone`), not a direct uncontrolled URL |
| Existing emojis | Preserve `emoji`; map known entries with a separate migration table and a generic fallback |
| Library maintenance | Curate search tags and categories without changing stable IDs |
| Accessibility | Every tile has a text label and keyboard focus; selection has an announced state |
| User uploads | Out of v2 scope until storage and safeguarding review; no implied permission to upload family photos |

## Specific design approvals to make

- Confirm which categories to expose and how many icons are shown initially. The **144 placements/115 unique vectors** above are a real starting library; your requested complete catalogue can expand to another approved subset without needing a new icon vendor.
- Decide whether duplicate assets should appear in more than one category (e.g. `camera` is useful in both Tech and Creative), or have one primary category and search tags.
- Decide whether the catalogue should show icon colours in Percy purple, or let the parent select from **approved colour presets**. The visual cannot change its shape or weight without a new registered asset variant.
- Decide where the picker appears within Create Reward and Edit Reward. A searchable sheet/dialog is likely more usable than 115 icons on one long form, but must be reviewed in a **running React preview**.
- Confirm if a curated **Plump Duo reward display** will coexist with the MIT user-selection library; production must not imply the user is choosing a Streamline asset until its exact picker use is licensed.
